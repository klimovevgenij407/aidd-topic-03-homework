### 3.3. Задание №4: Разработка новой функциональности

Оба агента реализовали все 4 требуемых модуля с веб-интерфейсом на Bootstrap 5, REST API на DRF, проверкой прав доступа по владельцу (`request.user`) и ограничениями целостности на уровне БД, но выбрали разную глубину проработки доменных моделей:

1. **Персональный мониторинг акций (`monitoring` в OpenCode vs `watchlist` в Qwen Code):**
   - **Модель данных:** OpenCode хранит целевую цену `target_price` и направление (`above`/`below`) непосредственно в `WatchlistItem` (одно условие на акцию внутри списка). Qwen Code разделил сущность элемента списка `WatchlistItem` (с полем заметки `note`) и целевого уровня `PriceAlert` (`1:N`), что позволяет задавать сразу несколько целевых порогов (например, верхний и нижний) для одной акции в одном списке.
   - **Дедупликация и повторное взведение:** OpenCode фиксирует переход состояния `condition_met: False -> True` и уникальность `(watchlist_item, price_snapshot)`, сбрасывая `condition_met = False`, как только цена отходит за порог. Qwen Code при срабатывании деактивирует алерт (`is_active=False`, `triggered_at=...`), защищает создание уведомления через `select_for_update()` + `UniqueConstraint(alert, price_snapshot)` и реализует **гистерезис повторного взведения (`PRICE_ALERT_REARM_MARGIN = 0.5%`)**, предотвращающий спам уведомлениями при мелких колебаниях цены вокруг порогового значения. Кроме того, Qwen Code отличает автоматически сработавшие алерты (`triggered_at__isnull=False`) от выключенных пользователем вручную.
   - **Удобство UI:** OpenCode добавил контекстный процессор `monitoring.context_processors.unread_notifications`, выводящий бейдж с количеством непрочитанных уведомлений в верхней панели навигации на всех страницах.

2. **Виртуальный инвестиционный портфель (`portfolio`):**
   - **OpenCode:** Построил расчёт портфеля по принципу хронологического журнала операций (`Portfolio` + `PortfolioTransaction`) с **поддержкой брокерской комиссии (`commission`)**, включаемой в среднюю цену приобретения `avg = (old_avg * old_qty + price * qty + commission) / new_qty` и вычитаемой из реализованного P&L. Пользователь может редактировать и удалять операции с полным пересчётом состояния, однако в модели `Portfolio` отсутствует учёт денежного остатка (`initial_cash` / `cash`).
   - **Qwen Code:** Реализовал полноценную модель с учётом денежных средств `Portfolio(initial_cash, cash)` + `Position(quantity, avg_price)` + `Transaction(realized_pnl)`. Каждая сделка выполняется в `transaction.atomic()` с блокировкой `select_for_update()`, проверяет достаточность свободных средств при покупке (`InsufficientFunds`) и бумаг при продаже (`InsufficientPosition`), а также рассчитывает полную стоимость портфеля (`equity = cash + market_value`) и процентную доходность (`return_pct`).

3. **История изменения рыночных цен (`dashboard` в OpenCode vs `market` в Qwen Code):**
   - Оба агента создали модель `PriceSnapshot(share, price, captured_at, source)` с уникальным ограничением `(share, captured_at)` и индексом `(share, -captured_at)`, реализовали автоматическую подгрузку 180 дневных свечей при нехватке данных в БД, расчёт статистики за выбранный период (первая/последняя цена, абсолютное и процентное изменение, минимум, максимум, количество точек; в OpenCode также рассчитывается среднее `average`) и рендеринг графика Plotly по данным из БД.
   - **Качество синтетического провайдера:** в OpenCode `SimulatedProvider` генерирует цены детерминированным случайным блужданием (`random.Random` от SHA-256 хеша FIGI), тогда как в Qwen Code `SyntheticProvider` моделирует реалистичный рыночный тренд суперпозицией длинной и короткой синусоидальных волн, внутридневного движения и детерминированного шума, формируя полноценные OHLCV-свечи (`open`, `high`, `low`, `close`, `volume`).

4. **Симулятор инвестиционных стратегий (`strategy`):**
   - **OpenCode:** Описывает коридорную стратегию прямо в модели `Strategy(share, buy_below, sell_above, initial_cash, quantity)` с проверкой `buy_below < sell_above`. При отсутствии позиции и `price <= buy_below` стратегия покупает на весь доступный капитал (или фиксированный `quantity`), а при наличии позиции и `price >= sell_above` продаёт всю позицию. Для наглядной демонстрации и ручного тестирования добавлена удобная management-команда `python manage.py set_price --ticker SBER --price 310`.
   - **Qwen Code:** Разделил стратегию `Strategy(share, initial_cash, cash, quantity, avg_price, realized_pnl)` и правила `StrategyRule(side, condition, threshold, quantity, is_active)` (`1:N`), позволяя комбинировать несколько правил покупки и продажи внутри одной стратегии. Правила со сделками защищены от удаления (`on_delete=models.PROTECT`), в каждой записи журнала `StrategyTrade` сохраняются `cash_after`, `position_after` и `realized_pnl`, а в UI и API предусмотрена кнопка ручного запуска проверки (`POST /api/v1/strategies/{id}/run/`).

**Почему OpenCode потратил в 2 раза больше токенов (600 тыс. против 300 тыс.) при той же модели `DeepSeek V4.1 Flash 1017`?**
1. **Объём сгенерированной документации и шаблонов:** OpenCode создал 7 отдельных подробных Markdown-документов (`ANALYSIS.md`, `MODERNIZATION.md`, `FEATURES.md`, `REPORT.md`, `WORKLOG.md`, `README.md`) общим объёмом ~118 КБ и 26 HTML-шаблонов, тогда как Qwen Code ограничился 4 документами (~98 КБ) и 15 шаблонами.
2. **Дополнительные исследовательские циклы в терминале:** OpenCode потратил серию шагов на поиск нового пакета `t-tech-investments` в реестре T-Bank, диагностику ошибки SSL/TLS цепочки сертификатов, установку gRPC-зависимостей и проверку живого соединения с `invest-public-api.tbank.ru`, а также на прогоны линтера и форматтера `ruff`.
3. **Особенности управления контекстом в CLI-оболочке:** OpenCode сохраняет в истории диалога более полные выводы промежуточных команд и прочитанных файлов на каждом шаге агентного цикла, что увеличивает кумулятивный размер входного контекста (`input tokens`) от итерации к итерации по сравнению с более компактным управлением историей в Qwen Code.

Проведённое сравнение на единой модели `DeepSeek V4.1 Flash 1017` показывает, что даже при идентичной LLM поведение AI Coding Agents существенно различается из-за устройства самого агента:

   - Когда требуется полная инфраструктурная упаковка проекта «под ключ» (`Dockerfile`, многосервисный `docker-compose.yml`, строгий линтинг `ruff`) и развёрнутая модульная документация с архитектурными диаграммами, а лимит токенов не является жёстким ограничением.
2. **Когда целесообразно выбрать Qwen Code:**
   - При разработке сложной бизнес-логики, финансовых расчётов, моделей данных со множественными связями (`1:N`) и транзакционными ограничениями, а также при необходимости получить высокое покрытие модульными тестами (`pytest`).
   - При работе в условиях ограниченных лимитов на токены или бюджет: **Qwen Code обеспечил сопоставимое (а в части доменной модели и количества тестов — превосходящее) качество кода при двукратной экономии токенов (300 тыс. против 600 тыс.)**.
3. **Оптимальная стратегия комбинирования:**
   - На практике наиболее эффективный результат даёт сочетание подходов: использование **Qwen Code** для проектирования доменных моделей, сервисного слоя, REST API и генерации обширного набора `pytest`-тестов при низком расходе токенов, и точечное привлечение **OpenCode** для инфраструктурного аудита, отладки внешних SDK, пакетной оптимизации запросов и настройки Docker/CI-окружения.
