## 2. Ошибки и проблемы, возникшие при работе

### 2.1. Окружение и зависимости

| Проблема | Проявление | Решение |
|---|---|---|
| Исходный проект не устанавливается | `tinkoff-investments==0.2.0b50` отсутствует на PyPI | Переход на `t-tech-investments==1.51.0` из реестра T-Bank |
| Реестр T-Bank отдаёт неполную TLS-цепочку | `pip` падал с `CERTIFICATE_VERIFY_FAILED` | `--trusted-host opensource.tbank.ru` в `requirements-marketdata.txt` |
| Нет PostgreSQL | исходные настройки требовали `localhost:5432` | SQLite по умолчанию, PostgreSQL через env |
| Нет Docker/Redis | нельзя запустить Celery worker/beat | синхронные команды `tick_prices`, `set_price`; Celery-конфигурация сохранена |
| Нет токена T-Invest | нельзя проверить реальные котировки | `SimulatedProvider` по умолчанию; живой провайдер проверен до авторизационной границы |
| Python 3.13 | старые Django/grpcio/protobuf несовместимы | обновление стека |

### 2.2. Ошибки в коде и тестах

1. **403 в тестах API после включения защиты.**
   Исходные 10 тестов ожидали анонимную запись. После `IsAuthenticatedOrReadOnly`
   шесть тестов упали с `403 Forbidden`. Тесты были переписаны: чтение проверяется
   анонимно, запись — с `force_authenticate`.

2. **Падение теста создания акции.**
   В `setUp` уже была акция `AAPL`, а тест создавал новую с тикером `aapl`.
   Из-за unique-ограничения форма возвращала 200. Исправлено на отдельный тикер
   и проверку реального списка.

3. **Ошибка в тесте Tinkoff-провайдера.**
   Фейковый SDK возвращал `None` вместо `CandleInterval`, из-за чего
   `get_daily_candles` падал с `AttributeError`. Добавлен фейковый enum.

4. **Локализованные числа.**
   При `LANGUAGE_CODE=ru-ru` `floatformat` выводит `500,00`, а тест ожидал
   `500.00`. Тест исправлен; это подтвердило, что локализация действительно
   применяется.

5. **Ошибка в `seed_demo_data`.**
   Переменная цикла `transaction` перекрывала импортированный
   `django.db.transaction`, из-за чего `transaction.atomic()` падал с
   `UnboundLocalError`/F823. Переменная переименована в `tx`.

6. **Повторный запуск `seed_demo_data`.**
   Из-за поиска операции по цене и дате появлялись дубликаты, а затем
   `MultipleObjectsReturned`. Команда сделана идемпотентной: демо-операции
   удаляются и создаются заново в фиксированном наборе.

7. **Валидация продажи в API.**
   В API-сериализаторе `executed_at` мог отсутствовать, из-за чего проверка
   «продажа больше остатка» пропускалась. Добавлено значение по умолчанию
   `timezone.now()`.

8. **Ссылка фильтра уведомлений.**
   Шаблон формировал `?` вместо переключения режима. Ссылка переписана на
   именованный URL/`?unread=1`.

9. **URL пользователя.**
   Исходный `path("user", include(...))` давал `/userlogin/` вместо
   `/user/login/`. Префикс исправлен на `user/`.

### 2.3. Принятые проектные решения

- Интеграция с T-Invest сохранена как полноценный опциональный провайдер.
- Для задания №4 график переведён с кэша ответа провайдера на сохранённую
  историю `PriceSnapshot`, чтобы история переживала перезапуски и не зависела от
  внешнего API.
- Для дедупликации уведомлений использовано состояние `condition_met`
  (переход false → true) плюс уникальность `(watchlist_item, price_snapshot)`.
- Для стратегий использована уникальность `(strategy, price_snapshot, side)`,
  чтобы повторная обработка снимка не создавала сделку-дубликат.
- API новых сущностей сделан с обязательной аутентификацией и фильтрацией по
  владельцу.

```bash

.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

Фактические результаты:

- миграции — `No changes detected`;

- `ruff check` — `All checks passed`;

Тесты не ходят во внешнюю сеть: провайдер подменяется моками/симулятором.
